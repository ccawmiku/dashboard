# 产品范围与验收

## 产品目标

用户维护一个服务器入口，把网络服务、局域网设备及后续传感器的数据变成稳定编号的数据点。小组件绑定这些数据点，独立设计外观。看板组织组件；不同设备按能力实现显示。

主要开发方式是由 AI 根据规范新增和修改模块，因此可理解的契约、可重复预览、明确边界和自动验证优先于复杂插件平台。

## 已确定的原则

- 第一种客户端是网页；网页与后端打包到同一个应用镜像。
- 第一阶段是单服务器、单应用实例、可信网络内使用。
- 数据只有服务器统一接入，客户端不持有天气或设备凭证。
- 数据连接器与视觉组件独立；一个连接器可以产出多个数据点，一个数据点可以供多个组件使用。
- 一个组件类型只有一种尺寸和外观。尺寸集合为 1×1、1×2、2×1、2×2，先宽后高。
- 外壳是统一主题的圆角矩形。固定网格占位不代表固定物理像素；不允许改变长宽格数。
- 同一组件类型可以创建多个实例，绑定不同数据或配置。
- 不把网页 DOM、React 组件或 CSS 当作跨设备协议。
- 一个仓库、main 开发、精确版本标签和版本镜像；初期模块统一构建发布。

## 首版用户流程

1. 启动容器，打开网页。
2. 页面展示看板名称、当前同步状态和一个 1×1 数字时钟。
3. 首次同步前显示等待状态，不伪装成已经获取 NTP 时间。
4. 同步成功后，显示小时、分钟、秒、日期和时区。
5. 网络异常时仍可依据最后的时间基准走时，但显著显示“连接中断”或“同步过期”。
6. 恢复连接后自动重新获取服务器时间，不要求刷新页面。

## 首版必须交付

- 完整中文项目文档及 AI 开发约束。
- 一个 NTP 连接器，具有超时、失败恢复、节流和关闭清理。
- 注册一个固定 ID 的时钟数据点。
- HTTP 快照、SSE 状态变更通知、健康检查。
- SQLite 保存看板和定义，首启幂等初始化。
- 一个 1×1 时钟组件，独立模拟预览和错误边界。
- 原生工具自动检查、浏览器测试、GitHub 容器构建与烟雾测试。
- 公共 GitHub 仓库和带精确版本的公共 GHCR 镜像。

## 首版明确不包含

拖拽编辑器、修改配置 API、账户与权限系统、第三方代码安装、沙箱插件、热更新、告警通知、历史曲线、设备注册、远程控制设备、安卓包及 ESP32 固件。SSE 仅通知变化，不承诺离线事件重放。

## 体验要求

- 中文默认界面；默认时区 Asia/Shanghai；内部时间保持 Unix 毫秒。
- 手机 320 CSS 像素宽度不横向溢出；桌面留有合理呼吸空间。
- 时钟使用等宽数字，数字变化不造成布局抖动。
- 错误与连接状态同时有文字提示，不能只靠颜色。
- 不对每秒变化使用屏幕阅读器即时播报；状态变化可以礼貌播报。
- 遵循 reduced-motion；首版不强制复杂动画。
- 不引入为填满页面而添加的虚假组件、假数据或装饰性指标。

## 性能与质量目标

以下是设计目标，不是未经测试的承诺：首次网页可交互应适合家庭网络；单个时钟浏览器每秒只更新本地视图；公共 NTP 默认每 5 分钟一次同步轮次；浏览器每 30 秒校准一次，每次页面恢复可见时重新校准。没有浏览器连接时服务器仍采集；浏览器数量不增加 NTP 请求频率。

首版为信息显示时钟，不提供计费、金融交易或实验测量级授时保证。
