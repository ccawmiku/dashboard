# 连接器开发规范

## 最小责任

连接器获取原始数据、校验、转换单位并输出标准结果。共享 SDK 描述生命周期和输出，不包含具体设备品牌。首版的 NTP 时间值比较特殊，但不能因此让每个新连接器复制 NTP 时间外推逻辑。

## 新增流程

1. 在 `connectors/<name>` 新建模块，声明实例配置和产生的数据点。
2. 选择官方 API 或设备支持接口；记录网络位置、认证方式及限流。
3. 使用运行时校验读取配置与响应。数值须有限，不允许 NaN、Infinity 或隐式字符串转换。
4. 显式转换原始单位；记录 sourceId 和采样/接收时间。
5. 实现 start / stop，确保同实例不会重叠采集。
6. 通过服务器组合入口注册，不修改任何组件实现。
7. 使用本地模拟服务测试成功、超时、错误格式和恢复。
8. 写明配置示例、必要网络权限和限制。

## 调度约定

常规采集采用“本轮结束后安排下一轮”，避免慢请求堆积。每个请求都有超时。正常间隔尊重来源限流；故障采用有上限退避，可加入抖动。用户客户端数量不得影响上游请求频率。

NTP 首版采用固定 5 分钟正常周期、失败后 30 秒至 5 分钟退避；配置的最短采集周期为 30 秒。每轮对服务器列表顺序回退，不并发轰炸公共服务。服务返回拒绝或限速时，不在本轮再次请求同一地址。

## 错误分类

推荐对外代码：TIMEOUT、DNS_ERROR、INVALID_RESPONSE、SOURCE_UNAVAILABLE、CONFIG_ERROR。内部日志可记录来源名称和安全诊断，但不记录密码、授权头、cookie、原始机密响应。

首版 NTP 对外统一 `NTP_UNAVAILABLE`；更详细原因由安全日志定位。跨所有配置源失败后才发布失败。成功发布清空 lastError。

## 数据与质量

最后有效值和最近尝试结果分别维护。获取失败不写入 0，不清除有效旧值。新鲜度按服务器单调时钟计算，不能仅靠可被系统校时影响的 wall clock。

普通指标未来建议 `observedAt`（来源时间）、`receivedAt`（平台收到时间）、`quality`、`expiresAfterMs`；来源不提供采样时间时必须明确标记使用接收时间。

## 安全边界

配置来自部署者的环境变量或受保护配置。首版没有用户输入 URL 的接口。未来允许配置任意 URL 时需要设计 SSRF 防护；由于路由器和 NAS 就在内网，不能简单禁止所有私有地址，需显式允许的目标范围。

连接器是受信任仓库代码，并非沙箱。发布模块之前检查依赖和权限。密钥只能在后端使用，不能进入 contracts 的公开结构和网页配置。

## 接入顺序建议

NTP → 一个天气服务 → 用户实际路由器 → 用户实际 NAS。天气验证普通数值、文本和缓存；设备连接器验证认证、离线状态和多个数据点。具体品牌与 API 应在对应任务中确认，不现在猜测。
