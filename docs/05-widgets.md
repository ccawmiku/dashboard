# 组件开发规范

## 类型、实例和固定尺寸

一个组件类型对应一份固定外观和一个网格尺寸。`digital-clock` 首版固定为 `{width:1,height:1}`。需要更大时钟时新增类型，而非向现有组件加入尺寸分支。

一个类型可被实例化多次，标题、时区和数据绑定不同。组件不得以全局变量保存实例状态。多个实例仅共享不可变定义和公共库。

## 组件包内容

- `manifest.ts`：纯数据，不能导入浏览器或后端专用模块。
- `index.tsx`：React 实现，通过 props 接收绑定后的观测和配置。
- `*.module.css`：组件私有样式。
- `fixtures.ts`：正常、过期、失败、无数据预览样本。
- 测试：展示关键语义及边界；不为每个 CSS 属性编写镜像断言。

首版文件可按规模合并，但职责必须清楚。新增第三种组件后评估生成脚手架，避免过早建立复杂 CLI。

## 输入接口

组件只能接收数据与配置，不能在内部 fetch 上游接口、建立独立 SSE、读 localStorage 作为隐藏配置或获取凭证。网页外壳统一负责通信和绑定检查。时钟还接收客户端校准时刻，以便使用单调时钟外推。

组件不直接修改看板或其他组件。未来需要交互时，通过明确的语义 action 回调，由外壳执行。

## 视觉系统

公共 ui 提供圆角卡片壳和 CSS 变量：背景、前景、弱化文字、边框、阴影、圆角、间距。首版采用深色平静视觉，时钟为主信息，绿色只表达同步正常。

数字使用 `font-variant-numeric: tabular-nums`，优先系统字体，不依赖远程字体服务。组件内容可根据格子的物理宽度调整字号，但网格形状和展示内容结构保持不变。

基础格保持正方形，跨格尺寸计算包含 gap。布局由看板外壳管理；组件不写页面级位置样式。首版单卡布局预留扩展，无拖拽依赖。

## 错误隔离与可访问性

每个实例包裹 ErrorBoundary，组件渲染失败只影响该卡片。异步事件错误也应在所属逻辑里处理，因为 ErrorBoundary 不捕获所有异步错误。

时间数字用语义 `<time>`；日期可读。状态使用文字和点状指示，状态区域 `aria-live=polite`，时间每秒更新不播报。页面控件使用语义链接、按钮、select 等原生控件；首版无复杂自绘交互控件，因此无需增加大型 UI 控件依赖。

未来编辑器需要对话框、菜单、拖拽等时，优先成熟可访问组件，单独评估体积与样式，不为首版时钟引入完整管理后台。

## 独立预览

`/?preview=clock&state=good|stale|error|unavailable` 使用明确标记的模拟数据，不访问真实 NTP。该页面便于 AI 开发和截图回归；不得将模拟状态伪装成真实同步。

验证至少覆盖：桌面、320px 手机、缺数据、长标题、失效时区、过期样本、组件错误、页面隐藏后恢复。实际支持范围以验证记录为准。

## 新增组件检查清单

1. 新类型 ID、版本和固定尺寸。
2. 声明数据输入 kind 与必需性。
3. 配置 schema，默认值与边界。
4. 仅通过共享接口接收数据。
5. 样式隔离，遵循主题和可访问性。
6. 四种状态模拟样本与独立预览。
7. 注册到网页和公开 manifest 列表。
8. 更新组件文档和必要测试。
