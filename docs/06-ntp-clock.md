# NTP 数字时钟设计

## 首版方案

服务器使用 `@hapi/sntp` 读取 NTP，作为标准连接器的首个实现。它只估算应用时间，不调用系统改时、特权模式或宿主机时间设置。生产容器不需要 SYS_TIME 权限。

浏览器无法直接使用此 UDP 客户端；由后端获取 NTP 后通过 HTTP 传递时间基准。默认候选服务器为 `ntp.aliyun.com,time.cloudflare.com`，可通过 NTP_SERVERS 修改。具体网络可达性取决于部署位置。

## 算法

NTP 交换包含客户端发送 T1、服务端接收 T2、服务端发送 T3、客户端接收 T4：

```text
offset = ((T2 - T1) + (T3 - T4)) / 2
roundTrip = (T4 - T1) - (T3 - T2)
```

由库校验响应并计算偏差，封装层还检查结果有限、层级有效、延迟有界。请求期间比较 wall clock 与单调经过时间，如果本地系统时间明显跳变，丢弃该次测量。记录成功时的校准 epoch 和 performance.now() 锚点。

运行中估算时间：`anchorEpochMs + (performance.now() - anchorMonoMs)`。不能持续用 `Date.now() + oldOffset`，否则系统后续校时会与旧偏差叠加。

这是使用单个有效来源的轻量 SNTP 方案，不是完整 NTP 多服务器选择、漂移驯服或认证授时实现。

## 浏览器校准

客户端用单调时钟测量 HTTP 往返时间，收到快照时将服务器的当前时间加上约半个 RTT 作为基准，再以 performance.now() 走时。半 RTT 假设上下行大致对称，只提供近似补偿。

网页每 250ms 检查时间，显示 HH:mm:ss。每 30 秒重新 HTTP 校准，页面恢复可见和 SSE 重连时立即校准。刷新画面与获取 NTP 无关。HTTP 校准超时会使连接状态变差，不切换成未标明的本机时钟。

页面休眠/后台时单调计时器在不同系统上的表现不一致；恢复可见必须重新校准。旧数据可暂时显示并标识重新连接，不能依靠隐藏页面的定时器保证精度。

## 状态机

| 情况                         | 质量                  | 数字                   |
| ---------------------------- | --------------------- | ---------------------- |
| 首次成功前                   | unavailable           | 占位                   |
| 首次失败且没有基准           | error                 | 占位                   |
| 最近成功且未超过新鲜度       | good                  | 正常走时               |
| 有旧基准，最近失败或基准过期 | stale                 | 继续估算，标记过期     |
| 浏览器连接服务器失败         | 客户端连接状态异常    | 保留旧基准，标记离线   |
| 后端重启                     | unavailable，重新采集 | 不把历史记录当作新同步 |

默认正常采样 300000ms，过期阈值 900000ms，请求超时 3000ms。失败退避从 30000ms 增长至 300000ms。限制配置范围，避免零间隔循环和公共源滥用。所有源失败后不再额外假装成功。

## 时区和日期

内部使用 UTC epoch，组件通过 Intl.DateTimeFormat 与 IANA 时区显示。默认 Asia/Shanghai。NTP 本身不提供“北京时间”这样的时区配置。小时使用 00–23，小组件显示年月日和星期。无效时区在配置阶段拒绝。

## 测试设计

- 本地 UDP 假 NTP 服务使用真实数据包交换，验证协议封装与超时；不依赖公网服务才能通过 CI。
- 注入查询函数和单调时钟，验证成功、失败、过期、恢复、停止和系统时间跳变。
- 浏览器测试通过 HTTP fixture 验证数字走时，客户端系统时间不能决定初始日期。
- 真实 NTP 测试单独执行并记录结果，不拿 fixture 冒充公网同步。
- 容器烟雾测试在 GitHub Actions 启动同网络的假 NTP 服务，验证容器内 UDP 采集、API 与静态网页。

## 限制

UDP NTP 没有加密身份认证，单个来源也不能抵抗错误或恶意授时；需要高可信时间时另行设计 NTS 或可信内网时间服务。系统初始日期应大致正确，跨 NTP era 的极端错误日期不属于首版承诺。同步校正允许显示时间小幅跳变；需要平滑调整时再添加显式策略。
