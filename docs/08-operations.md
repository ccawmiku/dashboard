# 部署运维

## 运行方式

推荐服务器 Docker Compose，镜像按精确 semver 固定。应用运行非 root，监听容器 TCP 3000，数据库使用 /data 命名卷。发布仅 linux/amd64；ARM NAS 或树莓派需新增构建目标后再支持。

Compose 默认映射到宿主机 127.0.0.1；局域网访问需显式设置 DASHBOARD_BIND=0.0.0.0。部署前确认服务器与路由器/NAS 在可达网络内。首版无身份系统，不直接面向公网。

## 配置

| 变量           | 默认                               | 含义                     |
| -------------- | ---------------------------------- | ------------------------ |
| HOST           | 127.0.0.1（容器 0.0.0.0）          | 后端监听地址             |
| PORT           | 3000                               | 后端 TCP 端口            |
| DATABASE_PATH  | data/dashboard.sqlite              | SQLite 路径              |
| NTP_SERVERS    | ntp.aliyun.com,time.cloudflare.com | 按顺序回退的主机名       |
| NTP_PORT       | 123                                | NTP 目标端口，测试可替换 |
| NTP_TIMEOUT_MS | 3000                               | 单次请求超时             |
| NTP_POLL_MS    | 300000                             | 正常采集周期             |
| NTP_STALE_MS   | 900000                             | 基准最大新鲜时间         |
| CLOCK_TIMEZONE | Asia/Shanghai                      | 首次创建默认组件时使用   |
| LOG_LEVEL      | info                               | 日志级别                 |
| DASHBOARD_BIND | 127.0.0.1                          | Compose 宿主机映射地址   |

环境变量在启动时校验，非法值直接报错退出。CLOCK_TIMEZONE 只影响首次初始化，不覆盖持久化配置；首版没有图形配置编辑器。更换 NTP 服务器后重启采集器即可，数据点 ID 不变。

## 网络

需要 DNS 解析和出站 UDP 123，响应流量需允许返回。只开放网页 TCP 端口；应用不是 NTP 服务器。企业云平台可能限制 UDP，应改用可达的 NTP 源或调整网络策略，不能悄悄用系统时间替代来源。

反向代理须关闭 SSE 缓冲并允许长连接；API 应禁用缓存。浏览器仅同源访问，无需开放任意 CORS。

## 存储和备份

配置持久化于 SQLite；最新时间基准在内存中，数据库保存最后同步诊断。每秒走时不写数据库。应用重启后需要重新采集。

SQLite 使用 WAL。最简单可靠的首版备份方式是停应用后复制完整数据卷；运行中备份需使用 SQLite backup API，不能只复制主 db 文件而丢失 WAL。恢复前保留原卷，先验证 schema 兼容。生产数据库不要放在 OneDrive、NFS 或多个写实例共享的路径。

## 更新和回退

1. 阅读目标版本兼容说明，备份数据卷。
2. 将 Compose 镜像版本改为目标标签。
3. 拉取并重建服务，检查 /healthz、网页和同步状态。
4. 数据库迁移后的回退必须检查兼容性，必要时从配套备份恢复。

首次公开发布需要确保 GHCR package 的可见性为 Public，并从匿名客户端验证 manifest 能读取。标签存在不代表镜像已经发布，检查对应 Actions。

## 故障定位

| 现象                   | 检查                                        |
| ---------------------- | ------------------------------------------- |
| 网页无法打开           | 容器状态、绑定地址、TCP 端口、防火墙        |
| 一直等待或显示同步失败 | DNS、出站 UDP、NTP 服务器、后端日志         |
| 时间持续走动但标记过期 | 最近 NTP 失败或超过新鲜度，走时是旧基准估算 |
| 日期时区不对           | CLOCK_TIMEZONE 首次配置及持久化看板配置     |
| 更新后配置消失         | 是否仍挂载原数据卷                          |
| API 正常但没有推送     | 代理缓冲、SSE 超时；HTTP 周期读取仍可工作   |

## 健康与日志

/healthz 表示进程存活，/readyz 表示本地初始化完成；NTP 故障不造成无限重启。具体源状态查看 snapshot 中的 quality 和 lastError。日志记录来源名、成功或失败、耗时等安全诊断，不记录密钥。

## 未来安全扩展

添加配置写入或敏感 NAS 指标前，设计用户认证、设备只读 token、访问范围和密钥存储。设备只接收绑定需要的数据，不能默认获得全量指标。首版公开时间数据的只读模式不能直接当作后续敏感数据的安全模型。
