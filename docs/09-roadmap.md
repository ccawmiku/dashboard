# 路线与验收矩阵

## M0：文档与时钟闭环（本次）

交付：架构文档、公共契约、NTP 连接器、固定 1×1 数字时钟、默认看板、SQLite、预览、Docker 和 CI。

验收：真实 NTP 可采集；模拟 UDP 可稳定测试；失败不伪造成功；时钟正常走时；固定尺寸；配置跨重启保留；匿名可拉取版本镜像。

## M1：验证接入扩展

加入一种天气来源和固定尺寸天气组件。引入 number/string 等明确数据类型，连接器一次产出多个点。新增来源不修改时钟；天气组件可用模拟样本独立预览。验证 API 请求限流、缓存和无凭证进入前端。

## M2：看板配置编辑

添加组件库、数据绑定、标题配置、移动排序和保存。先定义登录与写 API 权限，再开放编辑入口。只支持组件固定尺寸，不提供拉伸改变类型。网格布局负责碰撞和不同宽度的排列。

## M3：局域网设备

根据实际设备接入路由器和 NAS；区分 offline、timeout、unauthorized、unsupported。凭证留在后端。为趋势组件增加可配置历史采样、保留周期和容量控制。

## M4：第二种设备

依据用户硬件选择安卓或 ESP32。定义 device profile、组件支持列表、屏幕规格、主题限制、刷新周期和设备只读凭证。先复用一个时钟数据点，检验公开协议足够独立，不重写数据连接器。

## M5：按实际需求增强

插件安装、运行时隔离、多实例、远程管理、告警及更完整权限均需实际需求推动，不预先实现。

## 首版验收矩阵

| 范围     | 场景                         | 证据                   |
| -------- | ---------------------------- | ---------------------- |
| 配置     | 非法端口、周期、时区拒绝     | 单元测试               |
| NTP      | 真实 UDP 请求和有效响应      | 本地假服务器集成测试   |
| NTP      | 超时、首次失败、恢复         | 单元/集成测试          |
| 时间核心 | 时钟前进、过期、系统改时隔离 | 可注入单调时钟测试     |
| 存储     | 首启幂等、重开保留配置       | 临时 SQLite 测试       |
| API      | schema、404、健康、SSE       | Fastify 测试/HTTP 测试 |
| 网页     | 数字显示与走时、离线状态     | Playwright             |
| 布局     | 桌面、320px 无溢出、1×1      | 浏览器测试与截图检查   |
| 构建     | 类型、lint、格式、生产构建   | pnpm check             |
| 安全     | 依赖审计、秘密扫描           | 原生检查与 CI          |
| 容器     | UDP→API→静态网页、非 root    | GitHub Actions         |
| 发布     | 标签、公共镜像、匿名读取     | GitHub / GHCR 检查     |

## 后续任务切分原则

一次任务实现一个可独立验收的能力。新增数据源和新增组件可分开实施；完成时更新文档与验证记录。不要为了新增一个卡片，重构所有连接器或修改所有组件的输入。
